# 2026-11-03 ADC 改为硬件触发（注入组）

## 改造动机
原方案：TMR1_CH4 比较中断 → CPU 进 ISR → 软件触发 ADC 普通组 → 裸 while 轮询 OCCE。
问题：① 采样时刻受中断延迟影响，可能滑到开关沿采出满码 4095；
     ② VDDA 掉电时 ADC 不转换，裸 while 永久死等 → 中断卡死 → PWM 冻结 → 直流大电流。

## 新架构
TMR1 计数到 ARR-1 → CH4 比较事件（硬件直连，不产生中断）
  → ADC1 注入组自动转换 U/V/W
  → PCCE 标志 → ADC1_2_3_IRQHandler（读 JDT1~3）
  → 回调 foc_step

## 关键决策
- 用【注入组】而非普通组：AT32 普通组触发源只有 TMR1CH1/2/3，没有 CH4；
  注入组支持 ADC_PREEMPT_TRIG_TMR1CH4（同 STM32 TIM1_CH4→ADC 注入组→JEOC）
- ADC 中断优先级 = 1：SEGGER_RTT 的 BASEPRI=0x20 屏蔽优先级≥2 的中断
- 打开 CCR 预装载 tmr_output_channel_buffer_enable(CH1/2/3)：
  FOC 在 ADC 中断里写 CCR 时计数器已下行，不预装载会产生不对称怪脉冲
- curr_adc_calibrate() 期间禁用触发+中断（独占 ADC），结束后恢复
- CH4 中断不再使能，TMR1_CH_IRQHandler 保留但不会触发

## 待验证
CH4 在中心对齐下 ARR-1 会上下坡各匹配一次（间隔约 7ns），
可能产生双触发 → 若 irq 计数每 500ms 涨 10000 而非 5000，需把 CCR4 改为 ARR 或改用 TRGO。

- user/src/tmr1_pwm.c：关 CH4 中断、开 CCR 预装载
- user/src/main.c：注册回调改 curr_adc_set_done_callback，foc_step 去掉 curr_adc_sample()

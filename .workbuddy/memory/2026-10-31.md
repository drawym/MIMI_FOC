## 修复按键模块"多按几次卡死"（HardFault）

- 根因：`app_key.h` 里 `app_key_sub_t.q[APP_KEY_QUEUE_SIZE]` 用默认 8u，
  而 `app_key.c` 在 include 之后又 `#define APP_KEY_QUEUE_SIZE 64`，
  导致数组 8 条、掩码 `(64-1)=63`。head 在 0..63 循环，第 9 次入队即写 q[8]，
  依次踩坏 head(offset16)/tail(18)/notify(20..23)/notify_user(24..27)/sem(28+)，
  notify 变野指针后调用 → HardFault。与"多按几次"完全吻合（与消费快慢无关）。
- 修复：
  1. app_key.h 统一定义 `APP_KEY_QUEUE_SIZE 64u` + 2 的幂编译期 #error 校验；
  2. app_key.c 删除重复定义；`app_key_subscribe` 改成"先查重后找空位"（原顺序会把
     已在表中的应用重复插入，造成一次事件投递两份、信号量与队列错位 → 偶发丢键）；
  3. `app_key_pending` 改用无符号差 + 掩码；
  4. flexible_button.c：DOWN→MULTIPLE_CLICK 时清零 scan_cnt（原版保留按下时长，
     按住 >300ms 抬手会立即上报单击，双击永不成立）；register 上限 `>` 改 `>=`。
- 验证：预处理确认 `q[64u]` 与 `& (64u-1u)` 一致；全工程编译通过（FLASH 68480B），
  app_key.c / flexible_button.c 零告警。
- 遗留提示：main.c 的 `s_watcher_a` 未使用（告警）；PB4 默认 JTAG JNTRST，
  若读不到电平需补 `gpio_pin_mux_config(GPIOB, GPIO_PINS_SOURCE4, GPIO_MUX_0)`。

## 修复"串口完全无输出"（AT32 库 API 误用）

- 根因：AT32 固件库的 `usart_init()` **只写 baudr/ctrl1(db n)/ctrl2(stopbn)**，
  不置位 UEN / TDBEEN / RDBFEN（与 STM32 HAL 行为不同）。
  漏调使能函数 → 数据写进 dt 但引脚无波形，现象为"程序在跑但串口一个字节都不发"。
- 修复：`usart_log_init()` 中 `usart_init()` 之后补三行：
  `usart_transmitter_enable` / `usart_receiver_enable` / `usart_enable`，
  再开 RDBF 中断、置 `s_initialized`。
- 验证：反汇编 `usart_log_init` 确认调用序列
  crm→mux→gpio→usart_init→transmitter_enable→receiver_enable→usart_enable→中断→nvic。
  编译 FLASH 68704B / RAM 28176B。
- 经验：AT32 外设库的 `xxx_init()` 普遍"只配参数不使能"，移植 STM32 代码时必须补使能调用。

## FOC 电流遥测：中断只存数、线程负责打印

- 约束：`foc_step` 跑在 `TMR1_CH_IRQHandler` 里 10kHz（100us）。一行 20 字节在 115200
  下要 1.7ms，是控制周期的 17 倍 —— 直接在中断里 printf 必然拖垮 PWM 时序。
- 新增 `user/inc/foc_telem.h` + `user/src/foc_telem.c`：
  - `foc_telem_publish(iu,iv,iw)`：中断内调用，只有 3 次 16 位写，约 0.1us；
  - `foc_telem_read(&frame)`：seq-lock（写前 lock++ 变奇数、写后 lock++ 变偶数），
    线程读到的一定是完整帧，不需要关中断；重试上限 8 次；
  - `foc_telem_start(period_ms)`：建线程 `foc_tm`，栈 1024B、优先级 14（低于 main/按键/回显），
    默认 10ms → 100Hz，输出 `I 123,-456,789 mA\r\n`，同时同步一份到 RTT。
- 顺带修掉一个真实隐患：原 `foc_step` 里每 100 次中断做一次 `SEGGER_RTT_printf(0, "...%d,%d,%d")`，
  那是**在 10kHz 中断里做格式化**（虽然 100Hz，但单次几百 us 的抖动）。
  现在已删除，反汇编 `foc_step` 只剩
  `curr_adc_sample → curr_adc_get_amp×3 → foc_telem_publish → VF_step → set_ccr×3`，无任何 printf。
- 电流取值为 `curr_adc_get_amp()`（mA，int16），每次 2 次整数除法，三相共 6 次 ≈ 0.4us，可忽略。
- 电机停止时 `foc_step` 提前 return，不采样也不发布，因此遥测线程静默（避免刷屏）；
  KEY1 启动后才有数据。若要静止时看零漂，把 `curr_adc_sample()` 挪到早退之前即可。
- 验证：编译通过 FLASH 69496B / RAM 28200B，`foc_telem.c` 零告警；
  用 Python 穷举"发布插入读取的 7 个位置"验证 seq-lock 无半帧（全部一致或正确重试）；
  符号 `foc_telem_publish/read/start`、`foc_tm` 线程已链入。




## 停机态与串口精简（10-31 下午）
- 确认待机态：`motor_stop_output()` 三相 CCR=7200（ARR=14399 的一半）→ 三相零矢量。
  静止时线电压 0、无电流、无转矩，是正确且标准的待机状态。
  **但等价于三相绕组短接，不是"自由滑行"**：转子惯性旋转时会产生能耗制动电流。
  要真正高阻滑行必须 `tmr_output_enable(TMR1, FALSE)` 关 MOE（停机期间桥臂仍在 10kHz 开关）。
  已把 main.c 里那句错误注释"电机无电流自由停转"改成准确说明。
- 电机 10kHz 啸叫原因：人耳范围 20Hz~20kHz，10kHz 在内侧上段。静止时无相电流，
  声源主要是定子铁芯磁致伸缩 + 功率板 MLCC 压电效应（后者在小型驱动器里常更响）。
  判别法：拔掉三相线只留功率板通电，若仍叫则是板级 MLCC，与电机无关。
  两个可选降噪方案（未实施，待用户决定）：停机关 MOE / 开关频率提至 20kHz（ARR 变 7199）。
- 删除 `main.c` 的串口回显线程 `thread_uart_entry`（"uart"，512B，优先级 12）及其函数体，
  用户当前只需单向输出电流。连带清掉心跳残留的 `beat` 死变量。
  接收中断仍保留（环形缓冲自覆盖，无人读也不占资源）。FLASH 69496→69144B，RAM 不变（栈走堆）。
  仅剩 `s_watcher_a` 未使用告警（编译期被优化掉，0 字节占用，属预留占位）。

## 电流零点标定 + 码值直算（10-31 夜）
- 硬件事实核实（原理图 PDF + 网表，均已确认，非推测）：
  - 采样电阻 R14/R15/R16 = R2512 **5mΩ**，低端接 AGND（SESU_P 在 Q8 源极与 R14.2 之间）；
  - 运放 U11/U13/U15 = **INA181A1IDBVT**，A1 档增益 **20V/V**，REF 接 1.65V；
  - U7 = TLV9001 缓冲，R1/R2=20k/20k 从 A3.3V 分压 → REF=1.65V；
  - **A3.3V 与 ADC 的 VREF+（U17.13）同一网络** → 零点天生落在 VREF/2=2048 码，
    比例式设计，与 3.3V 实际值无关。
  - 链路：Vout = 1.65V + I×5mΩ×20 = 1.65V + I×100mV/A；满量程 ±16.5A；1 码=8.06mA。
- 用户实测相电流约 ±540mA → 只用满量程 3.3%，有效位数仅 ~7.2bit。
- 改动（用户要求"初始化后读零点、计算时减掉"）：
  - `curr_adc.c` 新增 `curr_adc_calibrate()`：电机静止时采 256 次取平均（约 1.3ms），
    得到每相零点码值 `s_offset_code[3]`；初值 2048（未标定也能跑）；
    带合理性校验（偏离标称 >150 码即整体回退并返回 0，防标定时电机在转）。
  - `curr_adc_get_amp()` 改为码值直算：`I(mA) = (raw - offset) × 33000 / 4095`，
    **offset 已含 1.65V 偏置，故不再减 1650mV**（易错点，勿重复减）；
    新增宏 `CURR_ADC_MA_SCALE = VREF×1000/(R×G)`，换 A2 档增益 50 时自动变 13200。
  - `main.c`：`curr_adc_init()` 之后调 `curr_adc_calibrate()`，结果经 USART_LOG 打印
    （`I0 calib OK: U=.. V=.. W=.. code`），失败则提示回退标称值。
- 验证：编译通过 FLASH 69440B / RAM 32280B；反汇编确认 main 内调用标定、
  foc_step 中断内仍只有 sample/get_amp×3/scope_push/VF_step/set_ccr，无打印。
  公式校核：分子最大 6.76e7，int32 余量 31.8 倍，无溢出。
- **更正此前一个夸大结论**：原以为"码值→mV→电流"两次取整会带来约 -4mA 系统性偏小，
  实测新旧算法差 ≤5mA（不到 1 个码），中段仅 1~2mA。真正起作用的是零点标定，
  码值直算只是顺带更干净。报告时已如实说明。
